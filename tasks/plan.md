## Решения

- TypeScript + Vite + CSS, один экран. UI-фреймворк и сервер для этого объёма не нужны.
- Модель: `Task { id: string; title: string; completed: boolean }`. Идентификаторы не зависят от названия: задачи с одинаковым текстом независимы.
- Список в памяти; чтение из `localStorage` при старте, запись после добавления, отметки и удаления. Один ключ приложения, например `digital-todo.tasks.v1`.
- Интерфейс: русскоязычная форма с добавлением по Enter, список с чекбоксами и удалением, пустое состояние. Читаемый текст, видимый фокус, удобные кнопки и адаптивная ширина.
- Пустой и пробельный ввод не добавляется; пробелы по краям убираются; названия выводятся как текст. Прочитанный JSON проверяется во время выполнения: одних типов TypeScript недостаточно.
- При недоступном хранилище приложение работает в памяти и предупреждает, что изменения могут не сохраниться. При повреждённых данных показывает предупреждение и пустой список, не перезаписывает данные при старте; следующее явное изменение может сохранить новый список. Последствия должны быть понятны из предупреждения.
- Дополнительные функции из границ `TASK.md` не включать. Библиотеки интерфейса пока не требуются.

## Порядок работы

### 1. Страница и инструменты

Подготовить Vite `vanilla-ts`, базовую форму и оформление; проверить совместимость локального Node.js и зависимостей. Сохранить существующие документы, зафиксировать зависимости lock-файлом.

**Готово:** страница открывается, форма и пустое состояние читаемы на узком и широком экране; сборка с проверкой типов проходит.
**Проверка:** `npm run build`, просмотр через `npm run dev -- --host 127.0.0.1`.
**Файлы:** `package.json`, lock-файл, конфигурация TypeScript, `index.html`, `src/`. Зависимостей от других этапов нет.

### 2. Добавление и восстановление

Реализовать ввод, независимые идентификаторы, список и модуль хранения. Проверить пустой ввод, структуру сохранённых данных и исключения при чтении/записи.

**Готово:** задача добавляется и остаётся после обновления; одинаковые названия не связывают задачи; ошибки хранения не ломают страницу.
**Проверка:** добавление и перезагрузка в браузере, небольшие тесты модуля хранения, сборка.
**Файлы:** `src/main.ts`, `src/storage.ts`, `tests/storage.test.ts`, файлы зависимостей. Зависит от этапа 1.
**Контрольная точка:** работает путь от ввода до сохранённой задачи.

### 3. Выполнение и удаление

Добавить чекбокс и кнопку удаления с понятными подписями; сохранять каждое изменение. Проверить обратное переключение в невыполненное состояние.

**Готово:** действия затрагивают только выбранную задачу и сохраняются после обновления, удалённая задача не возвращается.
**Проверка:** сценарий «добавить несколько → отметить одну → удалить другую → обновить», включая одинаковые названия; сборка.
**Файлы:** `src/main.ts`, `src/style.css`, браузерные тесты и их конфигурация. Зависит от этапа 2.
**Контрольная точка:** работают все четыре требования работодателя.

### 4. Удобство и граничные случаи

Довести адаптивность, клавиатурное управление и предупреждения хранения. Проверить длинные названия, HTML-символы и порядок фокуса после действий.

**Готово:** виден фокус, основные действия доступны с клавиатуры, на ширине 320 px нет горизонтальной прокрутки, длинный текст не прячет кнопки, пользовательский HTML не выполняется. В обычном сценарии нет ошибок консоли.
**Проверка:** целевые тесты и визуальный осмотр в браузере.
**Файлы:** `index.html`, `src/main.ts`, `src/style.css`, тесты. Зависит от этапа 3.

### 5. Независимая проверка и подготовка к сдаче

Проверяющий сопоставляет код и поведение с заданием. Основной агент исправляет воспроизводимые замечания, повторяет затронутые проверки и дополняет README реальными командами, ограничениями хранения и описанием AI.

**Готово:** чистая установка, проверка типов, тесты и сборка успешны; собранное приложение проверено в браузере; критерии `TASK.md` отмечены по фактам.
**Проверка:** `npm ci`, запланированные команды тестирования и `npm run build`, просмотр через `npm run preview -- --host 127.0.0.1`.
**Файлы:** `README.md`, `TASK.md`, `tasks/todo.md`; код — по замечаниям. Зависит от этапа 4.
**Контрольная точка:** локальный результат готов. GitHub и рабочий сайт — следующий шаг по отдельному указанию пользователя.

## Проверки и роли

Планируем небольшой Vitest-набор для ошибок хранения и проверки структуры данных, несколько Playwright-сценариев для пользовательских действий и перезагрузки. Не дублировать все проверки на обоих уровнях и не вводить норматив покрытия. Визуальный осмотр и клавиатурная проверка обязательны.

Предлагаемые scripts: `npm test -- --run` (Vitest), `npm run test:e2e` (Playwright). Браузерные тесты настроить на собранную версию, установку браузера документировать. Все команды в плане пока проектируемые: `package.json` отсутствует.

- **Основной агент:** реализация, проверки, исправления и актуальные документы.
- **Независимый проверяющий:** сценарии из задания, затем обзор кода и поведения после первого рабочего варианта. Получает требования, код и команды запуска. Не редактирует те же файлы параллельно.

Отдельные постоянные роли архитектора, дизайнера и DevOps для этого объёма не нужны. Документация ограничена существующими TASK/README/AGENTS, этим планом и коротким списком выполнения; отдельные ADR и PRD не требуются.

Справочные материалы: [Vite](https://vite.dev/guide/), [Vitest](https://vitest.dev/guide/), [локальный сервер Playwright](https://playwright.dev/docs/test-webserver), [localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).
