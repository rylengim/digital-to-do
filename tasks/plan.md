## Решения первого прототипа

- TypeScript + Vite + CSS, один экран. UI-фреймворк и сервер для этого объёма не нужны.
- Модель: `Task { id: string; title: string; completed: boolean }`. Идентификаторы не зависят от названия: задачи с одинаковым текстом независимы.
- Список в памяти; чтение из `localStorage` при старте, запись после добавления, отметки и удаления. Один ключ приложения, например `digital-todo.tasks.v1`.
- Интерфейс: русскоязычная форма с добавлением по Enter, список с чекбоксами и удалением, пустое состояние. Читаемый текст, видимый фокус, удобные кнопки и адаптивная ширина.
- Пустой и пробельный ввод не добавляется; пробелы по краям убираются; названия выводятся как текст. Прочитанный JSON проверяется во время выполнения: одних типов TypeScript недостаточно.
- При недоступном хранилище приложение работает в памяти и предупреждает, что изменения могут не сохраниться. При повреждённых данных показывает предупреждение и пустой список, не перезаписывает данные при старте; следующее явное изменение может сохранить новый список. Последствия должны быть понятны из предупреждения.
- Дополнительные функции ограничены согласованным продолжением ниже и `TASK.md`. Библиотеки интерфейса пока не требуются.

### 2. Добавление и восстановление

Реализовать ввод, независимые идентификаторы, список и модуль хранения. Проверить пустой ввод, структуру сохранённых данных и исключения при чтении/записи.

### 3. Выполнение и удаление

## Проверки и роли

В прототипе используются небольшой Vitest-набор для ошибок хранения и проверки структуры данных, несколько Playwright-сценариев для пользовательских действий и перезагрузки. Не дублировать все проверки на обоих уровнях и не вводить норматив покрытия. Визуальный осмотр и клавиатурная проверка обязательны.

Scripts: `npm test -- --run` (Vitest), `npm run test:e2e` (Playwright). Браузерные тесты настроены на собранную версию; установка браузера описана в README. Команды из плана реализованы в `package.json`.

- **Основной агент:** реализация, проверки, исправления и актуальные документы.
- **Независимый проверяющий:** сценарии из задания, затем обзор кода и поведения после первого рабочего варианта. Получает требования, код и команды запуска. Не редактирует те же файлы параллельно.

Отдельные постоянные роли архитектора, дизайнера и DevOps для этого объёма не нужны. Документация ограничена существующими TASK/README/AGENTS, этим планом и коротким списком выполнения; отдельные ADR и PRD не требуются.

Справочные материалы: [Vite](https://vite.dev/guide/), [Vitest](https://vitest.dev/guide/), [локальный сервер Playwright](https://playwright.dev/docs/test-webserver), [localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).
