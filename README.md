# To-Do List — тестовое задание The Digital

Отдельный локальный проект простого сайта со списком задач.

**Статус:** рабочий локальный прототип. Реализованы и независимо проверены четыре исходные функции, редактирование задач и несколько списков с переносом прежних данных. Следующие этапы: дизайн → GitHub Pages. Репозиторий и сайт ещё не опубликованы.

## Задание

Сайт должен добавлять задачи, отмечать выполненные, удалять задачи и сохранять состояние после обновления страницы. Использование AI-инструмента предусмотрено заданием.

[Точный текст задания и критерии приёмки](TASK.md).

## Выбранный технический подход

TypeScript + Vite + обычный CSS + `localStorage`. Одностраничное приложение работает в браузере. Задачи хранятся в браузере для адреса сайта; очистка данных сайта удаляет сохранённые задачи. Аккаунты, серверная база, авторизация и синхронизация между устройствами не предусмотрены.

Файлы приложения:

- `index.html` — разметка интерфейса;
- `src/style.css` — оформление и адаптивность;
- `src/main.ts` — действия с задачами, переключение списков и отображение;
- `src/list-controls.ts` — выбор, создание, переименование и удаление списков;
- `src/dom.ts` — поиск элементов интерфейса и общая защита клавиатурных действий при IME-вводе;
- `src/storage.ts` — чтение, проверка и сохранение данных;
- `tests/` — необходимые проверки основных сценариев.

## Редактирование задач

Кнопка с карандашом открывает поле названия прямо в строке задачи. «Сохранить» или Enter применяют изменение; «Отмена» или Escape возвращают прежнее название. После закрытия редактора фокус возвращается на кнопку редактирования.

Во время составного ввода через IME Enter не отправляет форму, а Escape не закрывает редактор. После завершения ввода обычные Enter/Escape работают штатно. Защита от преждевременной отправки действует также при добавлении задачи.

Пустое название отклоняется, пробелы по краям убираются. ID задачи и отметка выполнения сохраняются. Черновик не записывается в хранилище до сохранения — даже если в это время изменить другую задачу; обновление страницы отбрасывает черновик. Ошибка записи обрабатывается так же, как для других действий: появляется предупреждение о несохранённых изменениях.

## Несколько списков

Выберите текущий список в выпадающем поле. Кнопки рядом позволяют создать список, переименовать его или удалить. Пустое название отклоняется, пробелы по краям убираются; одинаковые названия допустимы, поскольку списки различаются по ID. Задачи, отметки выполнения и выбранный список восстанавливаются после перезагрузки.

Удаление требует подтверждения с названием списка и количеством его задач. «Отмена» и Escape оставляют данные без изменений. Последний список удалить нельзя. После удаления выбран соседний список.

При переключении сохраняются открытые редакторы задач и незавершённый текст в поле добавления каждого списка. Эти черновики остаются только в памяти страницы и исчезают после перезагрузки. Диалоги создания и переименования также защищены от преждевременного Enter/Escape при IME-вводе.

## Локальный запуск

Проверено с Node.js 22.22.3 и npm 10.9.8. Поддерживаемые версии Node.js указаны в `engines` файла `package.json` (22.12+ в ветке 22, либо 24/26+).

```bash
npm ci
npm run dev
```

Открыть **http://127.0.0.1:5173/**. Сервер слушает только этот компьютер; остановка — Ctrl+C в его терминале. Если порт занят, команда сообщит об этом, а не переключится на другой адрес с отдельным хранилищем.

Исходники написаны на TypeScript. Vite преобразует их в JavaScript для браузера; отдельный JS-прототип не требуется. Открывать `index.html` двойным щелчком не нужно — используйте локальный сервер.

## Проверки и сборка

```bash
npm test -- --run
npm run build
npx playwright install chromium
npm run test:e2e
```

Установка Chromium нужна один раз для браузерных тестов; загрузка требует доступа к сети. Playwright сам запускает собранное приложение на порту 4173 и останавливает тестовый сервер. Сборку нужно обновлять после изменения исходников. Порт 4173 во время проверки должен быть свободен.

`npm run build` проверяет типы и создаёт `dist/` с HTML, CSS и JavaScript. Для просмотра сборки отдельно: `npm run preview`, затем http://127.0.0.1:4173/.

Проверено 2026-11-09:

- чистая установка зависимостей через `npm ci`;
- 27 тестов Vitest: восстановление списков, проверка обоих форматов данных, перенос v1 → v2, приоритет текущего формата, ошибки доступа и записи;
- 21 сценарий Playwright в Chromium: исходные действия, редактирование, сохранение ID/статуса, отмена, изоляция черновиков, пустой/HTML-ввод, клавиатура и фокус, ширина 320 px, ошибки хранилища и IME; управление списками, подтверждение удаления, защита последнего списка, независимость одинаковых названий, восстановление выбранного списка и миграция, включая отказ первой записи;
- сборка с проверкой типов;
- визуальный осмотр пустого и заполненного списка на широком экране и при ширине 360 px; редактора и ошибки ввода — на широком экране и при ширине 320 px; управления списками — при 1280 и 320 px, диалога удаления — при 320 px;
- независимый обзор кода и браузерная проверка субагентом.

Исправление IME повторно проверено GPT‑6.1 Sol с уровнем рассуждения medium: полный набор тестов, независимые браузерные сценарии, обычные Enter/Escape после завершения композиции и пограничное событие `keyCode=229`. Два новых регрессионных теста воспроизводили ошибку до исправления и проходят после него.

После добавления списков GPT‑6.1 Sol medium повторил полный прогон и дополнительные браузерные сценарии: повреждённый v2 при наличии v1, отказ записи и повторная попытка, черновики добавления/редактирования при переключении и удалении их списка, IME/`keyCode=229` в диалогах, экран 320 × 568 px.

IME проверялся эмуляцией Chromium CDP; системные IME, реальные мобильные устройства и другие браузеры не проверялись. Полный аудит доступности не проводился. На этап дизайна оставлено замечание: при 320 × 568 px и названии списка из 240 символов диалог удаления прокручивается к кнопкам, уводя заголовок выше видимой области; предупреждение и действия остаются доступны.

## Хранение и ограничения

Состояние записывается в `localStorage` под ключом `digital-todo.state.v2`: версия формата, массив списков с их задачами и ID выбранного списка. У разных адресов, портов и профилей браузера разные данные: `localhost`, `127.0.0.1`, порт 5173 и порт 4173 не взаимозаменяемы. Очистка данных сайта удалит списки; в приватном режиме данные не предназначены для длительного хранения.

Если нового ключа ещё нет, приложение читает прежний `digital-todo.tasks.v1` и помещает задачи в список «Мои задачи», сохраняя ID, названия, порядок и отметки выполнения. При загрузке данные не записываются: первое действие сохраняет новый формат. Старый ключ остаётся нетронутым; при наличии нового ключа старый больше не читается. Ошибка первой записи не повреждает прежние задачи. Если новый формат повреждён, приложение предупреждает об этом, а не подменяет его устаревшими данными.

При повреждённых данных приложение предупреждает об этом и показывает пустой список. При загрузке ничего не перезаписывается; первое изменение создаёт новый сохранённый набор данных, о чём предупреждение сообщает заранее. При ошибке записи изменения остаются в памяти вкладки, а интерфейс показывает, что они могут пропасть после обновления. Следующее изменение повторяет попытку сохранения.

Синхронизации между вкладками и устройствами нет: при работе сразу в нескольких вкладках последняя успешная запись определяет сохранённое состояние всех списков. Приложение не отправляет задачи на сервер и не использует внешние шрифты или аналитику.

## Использование AI

Codex использован для подготовки плана, написания TypeScript/CSS/HTML, тестов и документации, запуска проверок и осмотра скриншотов. Независимый субагент Codex проверил план, код и основные сценарии в браузере. По итогам обзора исправлено обновление объявлений для экранных дикторов; регрессионная проверка включена в браузерный тест.

По указанию пользователя GPT‑6.1 Sol medium отдельно протестировал редактирование, обнаружил преждевременное сохранение при IME-вводе и повторно проверил исправленную версию. Исправление и регрессионные тесты подготовлены основным агентом.

Управление несколькими списками, перенос формата хранения и регрессионные тесты реализованы основным агентом Codex. GPT‑6.1 Sol medium выполнил независимый обзор и проверку исходных и расширенных сценариев.

Выбор стека и план согласованы пользователем. Личная проверка прототипа пользователем пока не подтверждена; автоматические проверки и обзор AI не выдаются за ручное тестирование человеком.
